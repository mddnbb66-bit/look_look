# 大屏缩放系统详解

项目采用 **CSS transform scale + 外层容器尺寸调整** 的方案来实现大屏缩放。

## 1. 核心 Hook：useZoom

`src/hooks/useZoom.ts` 是缩放逻辑的核心，它管理两种缩放模式：

```
┌─────────────────────────────────────────┐
│              useZoom Hook               │
├─────────────────────────────────────────┤
│  状态:                                   │
│  - autoFit: 是否自适应模式               │
│  - manualZoom: 手动缩放倍率              │
│  - fitScale: 自适应计算的倍率            │
│  - scale: 实际使用的倍率                 │
└─────────────────────────────────────────┘
```

### 自适应计算逻辑

```typescript
const computeFitScale = () => {
  const { clientWidth, clientHeight } = node  // 容器实际宽高
  const scale = Math.min(
    clientWidth / viewport.width,   // 横向比例
    clientHeight / viewport.height  // 纵向比例
  )
  // 取较小值，确保画布完整显示在容器内
}
```

核心思想：计算容器与画布的宽高比例，取较小值作为缩放比例，确保画布能完整显示在容器内。

### 返回值说明

| 返回值 | 类型 | 说明 |
|--------|------|------|
| `autoFit` | boolean | 当前是否处于自适应模式 |
| `manualZoom` | number | 手动缩放倍率（非自适应模式生效） |
| `fitScale` | number | 自适应计算得到的倍率 |
| `scale` | number | 实际使用倍率（autoFit ? fitScale : manualZoom） |
| `scaledWidth` | number | 画布在当前倍率下的宽度 |
| `scaledHeight` | number | 画布在当前倍率下的高度 |
| `handleZoomChange` | function | 手动调整缩放比例 |
| `handleResetZoom` | function | 重置为自适应模式 |

## 2. 缩放的 DOM 结构

编辑器 (`components/editor/Index.tsx`) 和预览页 (`components/preview/PreviewPage.tsx`) 使用相同的三层嵌套结构：

```
┌─ 外层容器 (可滚动区域) ─────────────────────────┐
│  overflow: auto                               │
│  ┌─ 缩放后尺寸容器 ───────────────────────────┐ │
│  │  width: scaledWidth   (viewport.width × scale) │
│  │  height: scaledHeight (viewport.height × scale)│
│  │  ┌─ 实际画布内容 ─────────────────────────┐ │ │
│  │  │  width: viewport.width (原始宽度)      │ │ │
│  │  │  height: viewport.height (原始高度)    │ │ │
│  │  │  transform: scale(scale)              │ │ │
│  │  │  transformOrigin: top left            │ │ │
│  │  │  position: absolute; inset: 0         │ │ │
│  │  │                                       │ │ │
│  │  │   [组件内容在这里渲染]                  │ │ │
│  │  │                                       │ │ │
│  │  └───────────────────────────────────────┘ │ │
│  └────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────┘
```

### 关键代码

```tsx
{/* 第二层：设置缩放后的占位尺寸 */}
<div style={{ width: scaledWidth, height: scaledHeight }}>
  {/* 第三层：实际内容，用 transform 缩放 */}
  <div style={{
    width: viewport.width,      // 原始宽度
    height: viewport.height,    // 原始高度
    transform: `scale(${scale})`,
    transformOrigin: "top left",
    position: "absolute",
    inset: 0,
  }}>
    <Renderer schema={schema} scale={scale} />
  </div>
</div>
```

## 3. 为什么需要两层容器？

| 层级 | 作用 |
|------|------|
| 外层容器 (`scaledWidth × scaledHeight`) | 提供正确的滚动区域尺寸，让滚动条正常工作 |
| 内层画布 (`transform: scale`) | 实际视觉缩放，保持组件内部坐标系不变 |

**如果只用 transform**：容器尺寸不变，滚动区域会出问题：
- 缩小时：出现大片空白
- 放大时：无法滚动查看被裁剪的内容

## 4. 拖拽组件如何适配缩放

`core/dnd/RndItem.tsx` 中把 scale 传给 `react-rnd`：

```tsx
<Rnd
  scale={scale}  // 关键：告诉 Rnd 当前缩放比例
  // ...
>
```

这样 `react-rnd` 在计算拖拽坐标时会自动除以 scale，确保鼠标移动距离与组件移动距离一致。

### 为什么需要传 scale？

当画布被缩放后，鼠标在屏幕上移动 100px，实际在画布坐标系中移动的距离是 `100 / scale` px。`react-rnd` 的 scale 参数会自动处理这个换算，保证拖拽行为符合直觉。

## 5. 缩放控制 UI

编辑器提供了完整的缩放控制：

- **自适应按钮**：切换 autoFit 状态
- **+/- 按钮**：每次增减 10%
- **重置按钮**：回到自适应模式

### 缩放范围

| 模式 | 最小值 | 最大值 |
|------|--------|--------|
| 手动缩放 | 0.1x (10%) | 3x (300%) |
| 自适应 | 0.05x (5%) | 5x (500%) |

## 6. 响应式适配

`useZoom` 使用 `ResizeObserver` 监听容器变化：

```typescript
const resizeObserver = new ResizeObserver(() => computeFitScale())
resizeObserver.observe(node)
window.addEventListener("resize", computeFitScale)
```

当浏览器窗口或容器尺寸变化时，自动重新计算自适应比例。

## 7. 数据流总结

```
用户操作 → useZoom 计算 scale → 更新 DOM 样式
                                ├─ 外层容器: width/height = 原始尺寸 × scale
                                └─ 内层画布: transform: scale(scale)
                                           ↓
                              拖拽组件接收 scale 参数，修正坐标计算
```

## 8. 方案优点

1. **组件内部坐标系不变** - 组件位置始终是设计稿尺寸，便于管理和持久化
2. **滚动行为正确** - 外层容器尺寸与视觉一致，滚动条正常工作
3. **拖拽精确** - react-rnd 支持 scale 参数自动修正坐标计算
4. **性能好** - transform 由 GPU 加速，不触发重排
